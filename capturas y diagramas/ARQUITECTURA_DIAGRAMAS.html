🔄 Ciclo de Vida de una Tarea:

  • 1. Usuario crea tarea: Rellena formulario en Nueva Tarea
  • 2. Guarda en TaskService: addTask() actualiza BehaviorSubject
  • 3. Se persiste: StorageService escribe en SQLite
  • 4. Se emite: TaskService dispara tasks$ a ListaTareas
  • 5. Se notifica: NotificationService programa aviso en Android

Estructura de las entidades principales almacenadas en SQLite:

🗂️ Características del Modelo:

  • Soft Delete: Las tareas eliminadas usan el campo deletedAt (no se borran de BD)
  • Auditoría Completa: TaskHistory registra TODAS las operaciones (create, update, complete, delete)
  • Multiusuario Ready: userId vincula datos con usuario autenticado
  • Internacionalización: USER guarda preferencias de idioma y tema

5. Estados de Tarea y Ciclo de Vida

Diagrama de estados que una tarea puede atravesar durante su vida en la aplicación:

stateDiagram-v2 [*] --> Pendiente Pendiente --> Completada: user completa Pendiente --> Papelera: user elimina (soft delete) Pendiente --> Editada: user modifica Completada --> Pendiente: user descompleta Completada --> Papelera: user elimina Editada --> Pendiente: cambios aplicados Editada --> Completada: cambios + completa Papelera --> Pendiente: user restaura Papelera --> [*]: vaciar papelera (hard delete) note right of Pendiente - Registrada en TaskHistory - Notificación activa - Visible en lista + calendario end note note right of Completada - Fecha completedAt guardada - Notificación cancelada - Visible en historial end note note right of Papelera - Soft delete (deletedAt != null) - No aparece en vista normal - Recuperable end note

🔄 Explicación de Estados:

  • Pendiente: Tarea nueva, sin completar. Es el estado inicial.
  • Completada: Usuario marcó como hecha. Se guarda timestamp de completado.
  • Papelera: Tarea eliminada (soft delete). Se puede recuperar o eliminar permanentemente.
  • Editada: Estado transitorio cuando se modifica. Vuelve a Pendiente o pasa a Completada.
